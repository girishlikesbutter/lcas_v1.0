# Attitude Inversion Experiment Roadmap

## The Problem

Given a synthetic light curve generated by our hi-fi forward model (Intelsat 901, known geometry, known BRDF, known orbit, known inertia), recover the initial attitude `q0` (3 DOF) and initial angular velocity `omega0` (3 DOF) that produced it. The satellite is tumbling (torque-free Euler dynamics). 6 parameters total.

## What We Already Know

From prior experiments (`exp3_basin`, `exp_chain7_tight`, `exp_two_epoch_matching`, etc.):

| Fact | Value | Source |
|------|-------|--------|
| Lo-fi vs hi-fi correlation | Spearman rho = 0.978 | exp3_basin |
| Lo-fi speedup | ~163x faster than hi-fi | exp3_basin |
| Attitude-only basin (omega fixed) | ~5-6 degrees | exp3_basin |
| Omega-only basin (attitude fixed) | ~0.02 deg/s | exp3_basin |
| Joint basin | < 1 deg + 0.001 deg/s | exp3_basin |
| Iso-brightness candidates per epoch | ~2000 from 10k seeds | exp_chain7 |
| Epoch-pair rotation-angle culling | ~99% per 7.2s bridge | exp_chain7 |
| DE/CMA-ES/dual annealing on 6D | All failed | multiple |
| Multi-start L-BFGS-B (joint, 5 deg) | 8/8 failed | exp3_basin |

**Test case**: "fast tumbler" omega = [0.5, -0.3, 2.0] deg/s, |omega| ~ 2.1 deg/s.

**Root cause of difficulty**: omega errors compound linearly with time. At delta_omega = 0.01 deg/s over 3600s, accumulated attitude error = 36 degrees — far outside the attitude basin.

## Two New Ideas Under Test

1. **L-parameterization**: Replace omega with angular momentum L_inertial in the parameter space. L is constant for torque-free motion, so perturbations in L don't compound over time. Hypothesis: convergence basin is 10-100x wider.

2. **Conservation filtering**: For torque-free motion, kinetic energy T and angular momentum vector L are conserved. Use these as filters on candidate pairs from epoch-chaining. Hypothesis: 50-90% additional culling beyond rotation-angle filtering.

## Design Principles

- **Each experiment is one standalone script**, 50-150 lines, runs in < 20 minutes
- **Each experiment answers ONE question** with a clear metric
- **Pivot points after each series** — don't build on unvalidated assumptions
- **Measure timing first** — no experiment should surprise you with runtime
- **Parallelise trials** — use `multiprocessing.Pool(N_WORKERS)` for independent trials
- **Truly fix parameters** when studying isolated basins (wrap the objective to freeze them)

## Series 1: Basin Characterization

The central question: **Is the convergence basin actually wider in L-space?** We measure this with controlled perturbation experiments, starting from the simplest case and building up.

### Exp 02 — Attitude-Only Basin (omega fixed at truth)
**File**: `exp02_attitude_basin.py`
**Time**: ~5 minutes
**Question**: What is the attitude convergence radius when omega is TRULY fixed?

This replicates the known ~5 deg basin result but with proper methodology:
- Fix omega at truth by wrapping the objective: `f(axis_angle) = full_objective([axis_angle, true_omega])`
- Only 3 parameters → 4 finite-difference evals per gradient
- 6 perturbation levels: [1, 2, 5, 10, 15, 20] degrees
- 8 random trials per level, maxiter=100
- Parallelise across N_WORKERS cores
- Report: success rate (converge to < 1 deg error) at each level

**Expected result**: ~100% success at 1-5 deg, dropping off by 10-20 deg.
**Why this matters**: Establishes the attitude basin as the ceiling — once omega is known, how close in attitude do we need to be?

### Exp 03 — Omega-Only Basin: Omega-Space vs L-Space
**File**: `exp03_omega_basin.py`
**Time**: ~10 minutes
**Question**: Is the convergence basin wider when we optimise over L instead of omega?

**THIS IS THE KEY EXPERIMENT.** Two sub-experiments, identical setup, different parameterization:

**Sub-experiment A (omega-space)**:
- Fix attitude at truth: `f(omega) = full_objective([true_aa, omega])`
- 3 parameters, maxiter=100
- 8 perturbation levels: [0.005, 0.01, 0.02, 0.05, 0.1, 0.2, 0.5, 1.0] deg/s
- 8 trials per level, parallelised
- Convergence criterion: omega error < 0.01 deg/s

**Sub-experiment B (L-space)**:
- Fix attitude at truth: `f(L) = full_objective_L([true_aa, L])`
- Convert each omega perturbation to equivalent L perturbation via `delta_L = R0^T @ (I @ delta_omega)`
- Same 8 levels, 8 trials, maxiter=100
- Convergence criterion: recovered omega error < 0.01 deg/s

**Output**: Side-by-side bar chart of success rates.

**Pivot point**:
- If L-basin is >= 3x wider → proceed to Exp 04 (joint L-space basin)
- If L-basin is roughly the same → L-parameterization is not the answer. Skip to Series 2 (time window / progressive refinement) and Series 3 (conservation filtering + other search strategies)

### Exp 04 — Joint Basin: Omega-Space vs L-Space
**File**: `exp04_joint_basin.py`
**Time**: ~15 minutes
**Question**: Does the L-space advantage survive when both attitude AND omega/L are free?

Only run this if Exp 03 shows a clear L-space advantage.

- Full 6-parameter optimisation, L-BFGS-B, maxiter=100
- Joint perturbation levels: [(1 deg, 0.01 dps), (3 deg, 0.05 dps), (5 deg, 0.1 dps), (5 deg, 0.5 dps), (10 deg, 1.0 dps)]
- 8 trials per level, parallelised
- Both omega-param and L-param versions
- Convergence: attitude < 5 deg AND omega < 0.1 deg/s

**Pivot point**:
- If L-param clearly wins → L-parameterization is our primary optimisation strategy. Proceed to Series 2 using L-param.
- If L-param does NOT help in joint space → the L advantage is only for the marginal (omega-only) problem and doesn't help in practice. Focus on search strategies (Series 3) instead.

## Series 2: Time Window Effects

Even if L-param helps, the basin may still be too narrow for a global search on the full 3600s window. Shorter windows have wider basins because errors don't accumulate as far.

### Exp 05 — Basin Width vs Window Length
**File**: `exp05_window_basin.py`
**Time**: ~10 minutes
**Question**: How much wider is the joint basin for shorter observation windows?

- Window lengths: [50, 100, 200, 500, 1000, 3600] seconds
- For each window: measure joint basin (best parameterization from Series 1)
- Use the joint perturbation levels from Exp 04
- 8 trials per level, parallelised
- Measure success rate at each (window, perturbation) combination

**Expected result**: Basin width scales as ~1/T (from the `delta_omega * T < 5 deg` analysis). At T=50s, the omega basin should be ~72x wider than at 3600s.

**Output**: Heatmap of success rate vs (window length, perturbation level).

**Why this matters**: If the 50s window has a basin of ~0.1 deg/s in omega, a modest grid search or DE run could find it. Then progressive refinement extends to the full window.

### Exp 06 — Progressive Window Refinement
**File**: `exp06_progressive_window.py`
**Time**: ~15 minutes
**Question**: Can we start from a short window (wide basin) and progressively extend to the full window?

- Stage 1: DE or multi-start L-BFGS-B on 50s window (wide basin)
- Stage 2: Refine result on 100s window
- Stage 3: 200s
- Stage 4: 500s
- Stage 5: 3600s (full)
- Test with various initial perturbation levels: [5, 10, 20, 45, 90, 180] deg attitude + [0.5, 1.0, 2.0] deg/s omega
- Use the better parameterization from Series 1

**Pivot point**:
- If progressive window works from 20+ deg initial error → this is our primary convergence strategy
- If it fails (gets stuck in local minima at short windows) → need better initialisation (Series 3)

## DECISION POINT 2: Do we have a viable convergence strategy?

After Series 2, we know:
- Whether progressive window refinement can converge from far away
- What initial accuracy we need for reliable convergence

**Path A** (progressive window works): We "just" need a coarse initial guess within ~20 deg attitude. Iso-brightness search + epoch chaining may already provide this.
**Path B** (progressive window fails): We need high-quality initialisation. Conservation filtering (Series 3) becomes critical. May need particle filter or multiple shooting.

## Series 3: Candidate Generation & Filtering

These experiments evaluate how well we can generate initial guesses from the light curve data, and whether conservation laws improve the filtering.

### Exp 07 — Iso-Brightness Candidate Statistics
**File**: `exp07_iso_brightness.py`
**Time**: ~5 minutes
**Question**: At one epoch, how many attitude candidates match the observed brightness? How close is the nearest one to truth?

- Pick epoch 0 (or a few different epochs)
- Run L-BFGS-B from N=2000 random starts to find iso-brightness attitudes
- Convergence: |predicted_mag - observed_mag| < 2*sigma
- Measure: total candidates found, nearest to truth, distribution of errors

**Output**: Histogram of attitude errors of iso-brightness candidates.

### Exp 08 — Two-Epoch Pairing Statistics
**File**: `exp08_pair_stats.py`
**Time**: ~10 minutes
**Question**: After pairing epoch 0 and epoch 1 candidates and filtering by rotation angle, how many pairs survive? How close is the best one to truth?

- Use candidates from Exp 07 (or regenerate at epochs 0 and 1)
- Pair all combinations, derive omega from rotation
- Filter by |omega| < FFT-derived bound
- Measure: pairs surviving, omega error of best pair, distribution

### Exp 09 — Conservation Filter Culling Power
**File**: `exp09_conservation_filter.py`
**Time**: ~10 minutes
**Question**: How many additional pairs does conservation filtering cull beyond rotation-angle filtering? Does it retain the truth?

Starting from the surviving pairs of Exp 08:
- Compute T and L_inertial for each pair
- Apply tiered filtering:
  - Tier 0: Rotation-angle only (baseline)
  - Tier 1: + energy consistency (|T - T_median| / T_median < 30%)
  - Tier 2: + |L| magnitude consistency
  - Tier 3: + L direction consistency (< 20 deg from mean)
- Report: count and truth-retention at each tier

**Pivot point**:
- If conservation filter culls >50% with truth retained → integrate into pipeline
- If conservation filter culls <20% → rotation-angle filtering is already tight enough, conservation adds little value

## Series 4: End-to-End Pipeline

### Exp 10 — Full Pipeline (Best Strategy)
**File**: `exp10_pipeline.py`
**Time**: ~20 minutes
**Question**: Can we recover (q0, omega0) end-to-end from the light curve?

Pipeline (assembled from best results above):
1. Generate iso-brightness candidates at epochs 0 and 1
2. Pair-match and filter (rotation angle + conservation)
3. For top-K candidates, run progressive-window optimization (or direct L-BFGS-B)
4. Rank by lo-fi residual, take top-5
5. Hi-fi refinement of top-5
6. Report: best attitude error, best omega error

**Success criteria**: attitude error < 5 deg AND omega error < 0.1 deg/s.

### Exp 11 — Robustness Check
**File**: `exp11_robustness.py`
**Time**: ~30 minutes
**Question**: Does the pipeline work for different initial conditions, not just our one test case?

- Test with 5 different (q0, omega0) combinations
- Vary noise levels: sigma = [0.02, 0.05, 0.10] mag
- Report: success rate across conditions

## Script Template

Every experiment script should follow this pattern:

```python
#!/usr/bin/env python3
"""Exp XX — [Title]. [One-line question]."""
import sys, time, json, numpy as np
from pathlib import Path
from multiprocessing import Pool

PROJECT_ROOT = Path(__file__).resolve().parent.parent.parent
sys.path.insert(0, str(PROJECT_ROOT))
import os; os.chdir(PROJECT_ROOT)

from lib.experiment_setup import setup_experiment, attitude_error_deg, save_results

# ── Config ──
N_TRIALS = 8
N_WORKERS = 8
SEED = 42

# ── Setup ──
t0 = time.time()
ctx = setup_experiment(n_observations=500, noise_sigma=0.05, random_seed=SEED,
                       true_omega_deg=(0.5, -0.3, 2.0),
                       end_time_utc='2020-02-05T11:00:00')
print(f"Setup: {time.time()-t0:.1f}s")

# ── Experiment ──
# ... (50-100 lines of actual experiment logic)

# ── Results ──
results = {...}
save_results(RESULTS_DIR / 'exp_XX.json', results)
print(json.dumps(results, indent=2))
```

Key rules:
- Print timing for EVERY step
- Save results incrementally (after each level, not just at the end)
- Use `multiprocessing.Pool` for independent trials
- Set `maxiter=100` for L-BFGS-B (not 300)
- When fixing parameters, ACTUALLY fix them (wrap the objective)
- Target: every script finishes in < 20 minutes
